## My Astron Collection UI Instance is Not Accessible

If you can't access your Astron Collection UI instance, there could be several causes. While this issue won't occur with Astron Collection Cloud (where our team manages the infrastructure), self-hosted instances might encounter configuration problems.

Let's go through the possible cases where your Astron Collection UI instance might be inaccessible:

### 1. Insufficient Storage Space

If you've made many deployments and don't have available space on your server, the Astron Collection database might enter recovery mode, preventing access to the user interface. Here's a quick solution to clear cache and free up server space:

```bash
docker system prune -a
docker builder prune -a
docker image prune -a
```

### 2. Container Race Condition During Restart

During a restart, a race condition might occur where Astron Collection's dependent containers don't start in the correct order. To troubleshoot this:

First, verify the running containers:
```bash
docker ps
```

You should see all three of these containers running:
```bash
2a5b955c32b6  ghcr.io/skygenesisenterprise/astron-collection:latest      "docker-entrypoint.s…"   4 days ago     Up 4 days     0.0.0.0:3000->3000/tcp, :::3000->3000/tcp                                                                             astron-collection.1.4bkuszk98muz372kw5mvwkw0h
5a989bf52bc6   postgres:16                 "docker-entrypoint.s…"   4 days ago     Up 4 days     5432/tcp                                                                                                              astron-collection-postgres.1.9hvjaxrmby7ex2denjtwo0csf
05be01c5612f   traefik:v2.5                "/entrypoint.sh trae…"   4 days ago     Up 4 days     0.0.0.0:80->80/tcp, :::80->80/tcp, 0.0.0.0:443->443/tcp, :::443->443/tcp, 0.0.0.0:8080->8080/tcp, :::8080->8080/tcp   astron-collection-traefik.1.2oktabjmfu558x2d2dy6czt8m
```

<Callout type='info'>
  **Note:** If you're running a version older than v0.29.9, you'll also see a `astron-collection-redis` container. Redis is no longer used in self-hosted Astron Collection since v0.29.9.
</Callout>

If all three containers are running but you still can't access the interface, it's time to debug:

### Debugging Process

#### 1. Check Container Logs
Start by examining the logs of each container:

```bash
docker service logs astron-collection # Astron Collection UI
docker service logs astron-collection-postgres # Postgres
docker logs astron-collection-traefik # Traefik
```

#### 2. Common Database Connection Issue

A common case is when the Postgres container starts after the Astron Collection container, preventing Astron Collection from connecting to the database. You might see logs like this when running `docker service logs astron-collection`:

```ts
> astron-collection@v0.22.3 start /app
> node -r dotenv/config dist/server.mjs

Default middlewares already exists
Network is already initilized
Main config already exists
Default traefik config already exists
Migration failed [Error: getaddrinfo ENOTFOUND astron-collection-postgres] {
  errno: -3008,
  code: 'ENOTFOUND',
  syscall: 'getaddrinfo',
  hostname: 'astron-collection-postgres'
}
Setting up cron jobs....
Main Server Error [Error: getaddrinfo ENOTFOUND astron-collection-postgres] {
  errno: -3008,
  code: 'ENOTFOUND',
  syscall: 'getaddrinfo',
  hostname: 'astron-collection-postgres'
}
```

To fix this, restart the Astron Collection service:
```bash
docker service scale astron-collection=0
# Then
docker service scale astron-collection=1
```

#### 3. Traefik Configuration Issues

If all containers are running but you still can't access the UI, and Astron Collection logs show no errors, the Traefik container might have configuration issues.

When running `docker logs astron-collection-traefik`, you might see errors like:

```shell
2025-04-07T15:20:18Z ERR Error occurred during watcher callback error="/etc/astron-collection/traefik/dynamic/astron-collection.yml: field not found, node: passHostHeader" providerName=file
```

First, try restarting Traefik:
```bash
docker restart astron-collection-traefik
```

If you still can't access it and the same error persists in the Traefik logs, you'll need to check the Traefik configuration. In this case, the error indicates that the `passHostHeader` field is missing in the configuration.

If you've modified any Traefik configuration for an `application` and added invalid configuration, the logs will point to the error. For example, the error above mentions `field not found, node: passHostHeader`, which means we need to manually modify the configuration files in `/etc/astron-collection/traefik`.

Here's an example of an invalid configuration:

```yaml
http:
  routers:
    astron-collection-router-app:
      rule: Host(`my-domain.com`)
      service: astron-collection-service-app
      entryPoints:
        - web
      middlewares:
        - redirect-to-https
    astron-collection-router-app-secure:
      rule: Host(`my-domain.com`)
      service: astron-collection-service-app
      entryPoints:
        - websecure
      tls:
        certResolver: letsencrypt
  services:
    astron-collection-service-app:
      loadBalancer:
        servers:
          - url: http://astron-collection:3000
          - passHostHeader: true
```

The correct configuration should be:

```yaml
http:
  routers:
    astron-collection-router-app:
      rule: Host(`my-domain.com`)
      service: astron-collection-service-app
      entryPoints:
        - web
      middlewares:
        - redirect-to-https
    astron-collection-router-app-secure:
      rule: Host(`my-domain.com`)
      service: astron-collection-service-app
      entryPoints:
        - websecure
      tls:
        certResolver: letsencrypt
  services:
    astron-collection-service-app:
      loadBalancer:
        servers:
          - url: http://astron-collection:3000
        passHostHeader: true
```

After fixing the configuration, restart Traefik:
```bash
docker restart astron-collection-traefik
```

You should now be able to access the user interface.


## Recreate astron-collection containers

In the case you want to recreate the astron-collection services, you can do the following:

<Callout type='warn'>
  **Important:** Before recreating services, make sure you have backups of your data. Recreating services will not delete your volumes, but it's always good to have backups.
</Callout>

### Recreate Postgres Service

Remove and recreate the astron-collection-postgres service:

```bash
docker service rm astron-collection-postgres

# Create a new astron-collection-postgres service with Docker Secrets
docker service create \
  --name astron-collection-postgres \
  --constraint 'node.role==manager' \
  --network astron-collection-network \
  --env POSTGRES_USER=astron-collection \
  --env POSTGRES_DB=astron-collection \
  --secret source=astron_collectionpostgres_password,target=/run/secrets/postgres_password \
  --env POSTGRES_PASSWORD_FILE=/run/secrets/postgres_password \
  --mount type=volume,source=astron-collection-postgres,target=/var/lib/postgresql/data \
  postgres:16
```

<Callout type='info'>
  **Note:** Using Docker Secrets is the recommended approach for managing sensitive data like passwords. The secret is encrypted and only available to services that have been granted access to it.
</Callout>


### Recreate Traefik Service

Remove the astron-collection-traefik service:

```bash
# If you are using docker standalone traefik
docker rm -f astron-collection-traefik

docker run -d \
    --name astron-collection-traefik \
    --restart always \
    -v /etc/astron-collection/traefik/traefik.yml:/etc/traefik/traefik.yml \
    -v /etc/astron-collection/traefik/dynamic:/etc/astron-collection/traefik/dynamic \
    -v /var/run/docker.sock:/var/run/docker.sock:ro \
    -p 80:80/tcp \
    -p 443:443/tcp \
    -p 443:443/udp \
    traefik:v3.6.25

docker network connect astron-collection-network astron-collection-traefik

# If you are using docker service traefik
docker service rm astron-collection-traefik

# Create a new astron-collection-traefik service
docker service create \
  --name astron-collection-traefik \
  --constraint 'node.role==manager' \
  --network astron-collection-network \
  --mount type=bind,source=/etc/astron-collection/traefik/traefik.yml,target=/etc/traefik/traefik.yml \
  --mount type=bind,source=/etc/astron-collection/traefik/dynamic,target=/etc/astron-collection/traefik/dynamic \
  --mount type=bind,source=/var/run/docker.sock,target=/var/run/docker.sock \
  --publish mode=host,published=443,target=443 \
  --publish mode=host,published=80,target=80 \
  --publish mode=host,published=443,target=443,protocol=udp \
  traefik:v3.6.25
```

### Recreate Astron Collection Service

Remove and recreate the astron-collection service:

<Callout type='info'>
  If the `astron_collectionauth_secret` secret doesn't exist on your server (installations older than v0.29.3), create it first: `openssl rand -hex 32 | docker secret create astron_collectionauth_secret -`
</Callout>

```bash
docker service rm astron-collection

# Create the astron-collection service
docker service create \
  --name astron-collection \
  --replicas 1 \
  --network astron-collection-network \
  --mount type=bind,source=/var/run/docker.sock,target=/var/run/docker.sock \
  --mount type=bind,source=/etc/astron-collection,target=/etc/astron-collection \
  --mount type=volume,source=astron-collection,target=/root/.docker \
  --secret source=astron_collectionpostgres_password,target=/run/secrets/postgres_password \
  --secret source=astron_collectionauth_secret,target=/run/secrets/astron_collectionauth_secret \
  --publish published=3000,target=3000,mode=host \
  --update-parallelism 1 \
  --update-order stop-first \
  --constraint 'node.role == manager' \
  -e POSTGRES_PASSWORD_FILE=/run/secrets/postgres_password \
  -e BETTER_AUTH_SECRET_FILE=/run/secrets/astron_collectionauth_secret \
 ghcr.io/skygenesisenterprise/astron-collection:latest
```

**For Proxmox LXC environments**, add the `--endpoint-mode dnsrr` flag to all services:

```bash
docker service create \
  --name astron-collection \
  --replicas 1 \
  --network astron-collection-network \
  --mount type=bind,source=/var/run/docker.sock,target=/var/run/docker.sock \
  --mount type=bind,source=/etc/astron-collection,target=/etc/astron-collection \
  --mount type=volume,source=astron-collection,target=/root/.docker \
  --secret source=astron_collectionpostgres_password,target=/run/secrets/postgres_password \
  --secret source=astron_collectionauth_secret,target=/run/secrets/astron_collectionauth_secret \
  --publish published=3000,target=3000,mode=host \
  --update-parallelism 1 \
  --update-order stop-first \
  --constraint 'node.role == manager' \
  --endpoint-mode dnsrr \
  -e POSTGRES_PASSWORD_FILE=/run/secrets/postgres_password \
  -e BETTER_AUTH_SECRET_FILE=/run/secrets/astron_collectionauth_secret \
 ghcr.io/skygenesisenterprise/astron-collection:latest
```



### Final Notes

While the specific issues may vary, the general troubleshooting approach remains similar to what we've described above, and is the general way we always follow when correcting a problem related to the astron-collection instance not starting.. If you still can't access the user interface:
1. Check that all containers are running properly
2. Review the logs of each container for specific error messages
3. Verify all configuration files
4. Make sure to read the Traefik documentation for detailed configuration options: https://doc.traefik.io/traefik/
